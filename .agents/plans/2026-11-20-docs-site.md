# Docs and download site Implementation Plan

**Status: finished.** Remaining one-time steps are listed under Status.

> **For agentic workers:** Use superpowers:executing-plans. Steps use checkbox (`- [x]`) syntax.

**Goal:** A Zensical site on GitHub Pages: a selling home page, a live download page, and the
existing docs, for people who have never heard of cecilia.

**Architecture:** `zensical.toml` at the repo root with `docs_dir = "docs"`; theme override in
`site-theme/` (`custom_dir`) holding `home.html`; site CSS/JS in `docs/assets/site/`. Download
data fetched client-side from the GitHub releases API by one small JS module shared by the home
page and the Download page. GitHub Actions builds with a pinned Zensical and deploys to Pages.

**Tech Stack:** Zensical 0.1.3 (Python, via `uvx`), plain CSS/JS, GitHub Actions
(`actions/upload-pages-artifact`, `actions/deploy-pages`).

**Spec:** `.agents/plans/2026-11-20-docs-site-design.md`

## Global Constraints

- Palette: paper `#FAFAF7`, graphite `#23262B`, brass `#B8862B`, string steel `#8A949E`.
- Font: Bricolage Grotesque (theme `font.text`), code font JetBrains Mono.
- `site_url = "https://kjmcnamara1.github.io/cecilia/"`; repo `kjmcnamara1/cecilia`.
- `docs/SPEC.md` excluded. `COMMANDS.md` / `OPTIONS.md` rendered unchanged (Rust tests read them).
- Pin `zensical==0.1.3` in CI and the mise task.
- Build must report "No issues found" (broken links are issues).

## Review Focus

- GitHub API down / rate-limited / JS off → buttons still lead to `/releases/latest` and the
  install one-liner is visible.
- Unknown OS (ChromeOS, BSD, phones) → no OS highlighted, all three shown, generic button.
- macOS on Apple silicon vs Intel → the universal `.dmg` serves both.
- A release missing an asset (e.g. AppImage job is `continue-on-error`) → that row is omitted,
  not a dead link.
- Narrow screens (phones) and dark scheme → home page readable, strings decoration not over text.

### Task 3: Download data module + Download page

**Files:** Create `docs/assets/site/releases.js`, `docs/download.md`.

**Interfaces:** `releases.js` sets `data-os` on `<html>` (`linux|macos|windows|unknown`) and fills
any element with `data-release="version"`, `data-asset="<key>"` (sets `href`, hides the closest
`[data-asset-row]` when missing), `data-download="primary"` (best asset for detected OS).
Asset keys: `dmg, appimage, deb, rpm, flatpak, snap, win-setup, win-zip, linux-tar,
mac-arm-tar, mac-x64-tar, install-sh, sums` matched by regex on asset names.

- [x] Static `href`s default to `https://github.com/kjmcnamara1/cecilia/releases/latest`.
- [x] Verify in a browser with the API reachable and with fetch failing (offline): links valid.
